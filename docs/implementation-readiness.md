### Resolved access rules

- Public Donor and Hospital registration create `PENDING` accounts with matching profiles atomically, without automatic login. - PENDING Donor/Hospital sessions are limited to status, permitted own-profile access, future password change, and logout. Donor own-profile read/edit is limited to full name, phone, address, area, and optional reported group; confirmed group stays staff-controlled. Hospital own-profile read/contact-only update is limited to contact name, phone, and address. Pending sessions have no operational actions; Admin Hospital reads require ACTIVE ADMIN separately.
- Login checks role/state and persists the new SID under Account lock. Protected guards now lock Account then the stored SID and check principal, tombstone and fresh post-lock expiry; profile writes repeat that check inside their domain transaction. Thus loaded sessions cannot pass a complete ACTIVE -> SUSPENDED -> ACTIVE cycle. The exact authorization point and already-in-flight read/write boundary are in the status guide.
- Audited suspension/reactivation are implemented backend-only with the exact ACCESS_RESTRICTED/ACCESS_RESTORED reasons.
