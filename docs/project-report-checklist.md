# Project Report and Academic Handoff Checklist

This is a documentation checklist, not evidence that the report or implementation is complete. Items are separated by source: the review checklist identifies college submission requirements, while PPT and GitHub URL are user-requested deliverables.

## College submission requirements (from the supplied project review and recovered college instructions)

- Include every member's full name and register number, plus a contribution table that records each member's work.
- Include the thirteen report sections in the exact order transcribed below from the user-provided college instructions.

### Exact report order and section contents

1. **Cover page:** Project title, course name, all members' names and register numbers, department, college, and academic year.
2. **Bonafide certificate:** Signed by the faculty in-charge.
3. **Abstract:** 150 to 200 words.
4. **Table of contents and list of figures.**
5. **Introduction:** Background, problem statement, objectives, and scope.
6. **Requirement analysis:** Modules, functional requirements, hardware and software requirements, front end, back end, and tools used.
7. **Database design:** ER diagram, relational schema, and normalization steps up to 3NF.
8. **Implementation:** SQL scripts (DDL, DML), views, stored procedures, functions, triggers, and database connectivity code, with explanation.
9. **Front-end design:** Description of each module and screen.
10. **Output screenshots with explanation:** Every screen and query output.
11. **Testing:** Test cases with input, expected output, actual output, and status.
12. **Conclusion and future enhancements.**
13. **Contribution of members:** Table showing each member's work.

- Deliver both DOCX and PDF versions, using the college filename pattern `GroupNo_ProjectTitle_Report` for each file. Confirm the exact group-number and project-title spelling with the college template.
- Include a ZIP containing the complete project source code and SQL needed to create and populate the database.
- Submit one consolidated report prepared jointly by all group members.
- Submit a printed/spiral-bound report to the lab in-charge.
- Attend the live lab demonstration; all members must be present. Each member must explain database design, SQL queries, connectivity, and their own contribution.
- Create the database fresh from the submitted SQL during the demonstration if asked.
- Ensure every member can explain their contribution and participate in the project viva.
- Keep regular backups of the project code, database, and report materials.

### Report formatting requirements

- Times New Roman, 12-point body text.
- Bold 14-16-point headings.
- 1.5 line spacing.
- Page numbers centered at the bottom.
- Numbered figure/table captions.
- Monospaced code and SQL, such as Courier New 10-point.

## Additional user-requested deliverables

- Prepare a presentation deck (PPT).
- Include the GitHub repository URL in the handoff/report.

The review checklist distinguishes these from requirements attributed to the college submission section; retain that source distinction unless the college handout confirms otherwise.

## Completion tracking

The section titles/order below were transcribed from user-provided college instruction text. Database rebuild evidence, screenshots, query outputs, test results, source/SQL archive, DOCX/PDF, PPT, printed copy, and viva preparation must be marked complete only when actual artifacts or observations exist. Planned screens and SQL placeholders do not count as evidence.
